# Contributing to Lantern
- Branch from `main`; use short-lived branches (`feature/...`, `fix/...`, `docs/...`).
- Commit messages follow Conventional Commits: `type(scope): description`
(feat, fix, docs, refactor, test, chore), subject of 50 characters or fewer.
- One logical change per commit; explain *why* in the body.
- Never force-push or rewrite pushed history. Never commit secrets.
- Every change goes through a pull request with `Closes #n` and one approval.
